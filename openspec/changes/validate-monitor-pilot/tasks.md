## 1. Pilot protocol and gate

- [ ] 1.1 Define production-workflow eligibility, owner commitment, release cadence, and exclusion criteria
- [ ] 1.2 Define proceed, iterate, and stop thresholds before recruiting participants
- [ ] 1.3 Define the complete journey milestones and evidence fields for every participant
- [ ] 1.4 Review and freeze the protocol with the product owner before enrollment

## 2. Privacy and operations

- [ ] 2.1 Write the pilot data notice covering allowlisted prompt-free fields, access, retention, deletion, and temporary tooling
- [ ] 2.2 Create participant consent, withdrawal, export, deletion, and incident procedures
- [ ] 2.3 Build a separated participant-contact register and pseudonymous cohort ledger
- [ ] 2.4 Define access controls and an audit log for every manual report-handling operation
- [ ] 2.5 Verify schemas reject raw prompts, arbitrary metadata, and unsupported reports

## 3. Pilot delivery kit

- [ ] 3.1 Create onboarding for SDK installation, workflow naming, release metadata, sinks, and maturity
- [ ] 3.2 Create a repeatable retained-report and before/after comparison procedure
- [ ] 3.3 Create a material-regression notification and delivery-failure procedure
- [ ] 3.4 Create a weekly prompt-free cost summary template with assumptions and caveats
- [ ] 3.5 Create the baseline approval and CLI policy handoff procedure
- [ ] 3.6 Record every manual intervention so assisted value can be separated from product value

## 4. Cohort execution

- [ ] 4.1 Recruit three to five qualifying teams without counting ineligible or non-production candidates
- [ ] 4.2 Run one-team onboarding as an operational dry run without silently changing success thresholds
- [ ] 4.3 Onboard the remaining cohort and track installation through mature measurement
- [ ] 4.4 Deliver comparisons, one useful regression opportunity, weekly summaries, and CI handoff where evidence allows
- [ ] 4.5 Conduct structured follow-up on action, quality validation, retention, return behavior, and willingness to pay

## 5. Decision and cleanup

- [ ] 5.1 Score each participant and the cohort against the predeclared gate, weighting behavior over praise
- [ ] 5.2 Record a proceed, iterate, or stop decision with supporting and contradictory evidence
- [ ] 5.3 If proceeding, identify only the minimum workflows that require Monitor automation
- [ ] 5.4 Export participant data when requested and delete all expired or withdrawn data on schedule

## 6. Verification

- [ ] 6.1 Audit consent, access, retention, deletion, intervention, and milestone records for completeness
- [ ] 6.2 Run typecheck, tests, and builds for any pilot tooling and verify prompt-free canaries end to end
